SECTION 04 · 핵심

가변 vs 불변 — 같은 객체가 바뀌는가?

3주차에서 가장 중요한 섹션

여기를 잡으면 파이썬의 객체 모델 90%가 풀립니다. 잘못 이해하면 이후 리스트 복사와 함수 인자에서 같은 실수를 반복하기 쉽습니다.

두 종류의 객체

파이썬의 모든 객체는 두 부류로 나뉩니다:

  • mutable (가변): 객체 자체의 내용을 바꿀 수 있음 — list, dict, set
  • immutable (불변): 한 번 만들면 절대 못 바꿈 — int, float, str, tuple, bool

1주차 s8에서 "hello".upper()가 원본을 안 바꾸고 새 문자열을 돌려준다고 했죠? 이제 이유가 풀립니다. 문자열은 불변(immutable)이기 때문입니다. 기존 문자열의 내용을 직접 바꿀 수 없으므로, 문자열을 변환하는 연산은 변경된 내용의 문자열 결과를 돌려줍니다.

이 섹션의 핵심 (★ 매우 중요)
  • mutable: list, dict — 객체 자체 변경 가능 (id 그대로).

컴프리헨션 확장 — list, dict, set

앞에서 리스트 컴프리헨션을 봤습니다. 같은 생각을 딕셔너리와 set에도 사용할 수 있습니다. 실무 Python 코드에서 자주 보이므로 먼저 일반 for문으로 이해한 뒤 짧고 읽기 쉬울 때만 사용하는 습관이 좋습니다.

괄호가 ()이면 튜플 컴프리헨션?

아닙니다. (n * n for n in numbers)는 generator expression(제너레이터 표현식)입니다. 제너레이터는 나중에 배울 주제이므로 지금은 "튜플 컴프리헨션은 없다" 정도만 기억하면 됩니다.

모양으로 구분하기
  • [표현식 for ...] → list comprehension
  • {키: 값 for ...} → dict comprehension
  • {표현식 for ...} → set comprehension
  • (표현식 for ...) → generator expression (튜플 아님)

조심할 함정 — mutable을 함수에 넘기면

3주차에서 익힌 것
  • 리스트: [], 인덱싱, 슬라이싱, append, sort, in, for
  • 리스트의 진짜 모습: 박스 안엔 참조만, 요소는 별개 객체
  • 튜플: (), 잠긴 슬롯, 다중 할당
  • ★ 튜플의 진실: 슬롯은 잠겼지만 mutable 요소는 변할 수 있음
  • ★ 가변 vs 불변: append vs +, 같은 객체 다른 이름표
  • 딕셔너리: 키-값 매핑, 빈도 누적 패턴
  • 함수 def: 매개변수, return, 다중 반환
  • 매개변수의 모든 것: 위치/키워드/기본값/다중 할당

4주차에서는 None, 리스트·문자열 심화 도구, 그리고 외부 인터넷에서 데이터를 가져오는 API 호출로 가볍게 마무리합니다.
